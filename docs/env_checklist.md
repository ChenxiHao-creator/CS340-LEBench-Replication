Environment Precheck Checklist

This checklist is generated by precheck.sh to record and verify the baseline environment before running LEBench performance tests. Since benchmark results are highly sensitive to system configurations, tracking these 6 key metrics helps analyze test results, troubleshoot performance fluctuations, and ensure experiment reproducibility.

Kernel Version
Command: uname -r
Purpose: Confirms the running Linux kernel version. Different kernel versions can have varied scheduling algorithms, memory management, and security patch implementations (like KPTI), which directly impact benchmark performance.

Boot Command Line (Cmdline)
Command: cat /proc/cmdline
Purpose: Shows the kernel boot parameters. This is critical for benchmarking; for example:

Whether KPTI is disabled (pti=off).

Whether specific hardware features are disabled (e.g., nomodeset).
These parameters significantly alter the system's security state and performance overhead.

KPTI Status (Kernel Page Table Isolation)
Command: dmesg | grep -q "Kernel/User page tables isolation: enabled"
Purpose: Checks if Kernel Page Table Isolation (KPTI) is enabled. KPTI mitigates the Meltdown vulnerability but introduces performance overhead for syscalls and interrupts. When testing low-level performance like memory or context switching, having KPTI enabled or disabled (pti=off) can cause massive differences in results.
Status:

enabled: KPTI is on (security first, slight performance drop).

disabled / pti=off: KPTI is off (performance first, often disabled in experiments for maximum throughput).

CPU PCID Support (Process Context IDentifiers)
Command: grep -q "pcid" /proc/cpuinfo
Purpose: Checks if the CPU supports PCID. PCID allows the CPU to cache TLB entries, which heavily mitigates the performance penalty of page table switching when KPTI is enabled. If the CPU lacks PCID support, enabling KPTI will cause a very noticeable performance drop.

CPU Governor
Command: cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
Purpose: Views the CPU power/frequency scaling policy (e.g., performance, powersave, ondemand). For benchmarks, setting it to performance (pinning to max frequency) is highly recommended to prevent fluctuating test results caused by dynamic frequency scaling.

Current Frequency
Command: lscpu | grep "MHz"
Purpose: Records the current real-time CPU frequency (MHz). Combined with the governor setting, this confirms if the hardware is running in the expected performance state.
